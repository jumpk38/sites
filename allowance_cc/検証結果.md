## 3. 発見した不具合と修正

### 【不具合】年利の入力欄が空のまま保存すると、警告なく 0% になる

| 項目 | 内容 |
|---|---|
| **深刻度** | 高(アプリの中核機能が停止する) |
| **発見箇所** | 保護者ページ → 年利の設定 |
| **該当関数** | `saveRate()` |

#### 症状
年利の入力欄を空にして「保存」を押すと、バリデーションを通過して **年利が 0% に設定される**。
さらに「年利を 0% に設定しました」と成功メッセージまで表示されるため、
保護者が誤って設定したことに気づけない。

以降アプリを何か月開いても利息が一切つかなくなり、
本アプリの主目的である「複利で増える体験」が失われる。原因も特定しにくい。

#### 原因
```js
const v = Number(document.getElementById('p-rate-input').value); // Number('') === 0
if (!isFinite(v) || v < 0 || v > 100) { /* 弾く */ }
```
JavaScript では `Number('')` が `0` を返すため、**空欄が「0% の明示的な指定」と区別できていなかった**。
`isFinite(0)` は `true`、範囲チェックも通過するため、そのまま保存されていた。

なお `<input type="number">` は不正な文字列を入力すると `value` が空文字になる仕様のため、
「abc」などの文字入力も同じ経路で 0% になっていた。

#### 修正
空文字を数値変換の**前に**弾き、拒否時は入力欄を現在の設定値に戻すようにした。

```js
function saveRate() {
  // 空欄は Number('') === 0 になるため、0% の指定と区別して先に弾く
  const raw = document.getElementById('p-rate-input').value.trim();
  const v = Number(raw);
  if (raw === '' || !isFinite(v) || v < 0 || v > 100) {
    toast('0〜100の数値を入力してください');
    document.getElementById('p-rate-input').value = state.bank.annualRate;
    return;
  }
  state.bank.annualRate = v;
  saveState();
  toast(`年利を ${v}% に設定しました`);
}
```

**意図的な 0% の設定は従来どおり可能**(0% にしたい保護者の操作は妨げない)。
`index.html` と `index_backup.html` の両方に適用済み。

#### 修正後の再検証(7項目・全通過)
| 検証項目 | 結果 |
|---|---|
| 通常値(8%)を保存できる | 通過 |
| 空欄では年利が変わらない | 通過 |
| 空欄拒否後、入力欄が現在値に戻る | 通過 |
| 文字入力でも年利が変わらない | 通過 |

| 意図的な 0% は設定できる | 通過 |

## 7. 結論

- **中核である利息の複利計算は、手計算値と完全に一致**しており、年またぎ・端数処理・
  二重加算防止・時計のずれといった境界条件でも正しく動作する
- **お金の整合性**は、アプリの残高を信用せず履歴から独立に再計算した値と一致することを確認した
- 発見した不具合1件(年利の空欄が0%になる)は修正し、再検証で全項目通過
- 異常なデータや不正な入力でアプリが壊れる経路は見つからなかった

**実機で使い始められる状態と判断する。**
