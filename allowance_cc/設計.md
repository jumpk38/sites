# おこづかい家計簿アプリ 設計書

## 1. 概要

小学3年生の娘1人が使う、おこづかい家計簿アプリ。
おさいふ(手元のお金)の収支記録に加え、**疑似口座(ぎんこう)** にお金を預けると
月ごとの複利で利息が増える体験ができる。

- 対象端末: iPad mini / スマートフォン(タッチ操作前提、PC対応不要)
- データ: `localStorage` を正とし、任意で Google スプレッドシートへ自動同期(§11)
- ユーザー: 1人固定(切り替えなし)
- 表記: 小3レベルの漢字+ふりがな不要な範囲のひらがな混在

## 2. 技術スタック

| 項目 | 選定 | 理由 |
|---|---|---|
| 構成 | **単一 `index.html`**(HTML/CSS/JS すべて内包) | ビルド不要・サーバ不要。ファイルを開くだけ/簡易ホスティングだけで動く |
| フレームワーク | なし(Vanilla JS) | 依存ゼロでオフライン動作が確実 |
| 保存 | `localStorage`(キー: `okozukai-app-v1`) | 即応・オフライン動作のため正の保存先とする |
| 同期(任意) | Google Apps Script + スプレッドシート | 子どもに Google ログインをさせずにデータを複製できる(§11) |

## 3. 画面構成(下タブ4つ)

```
┌─────────────────────────┐
│  ヘッダー(アプリ名)        │
│                         │
│  各タブの内容              │
│                         │
├─────┬─────┬─────┬─────┤
│ホーム │きろく │ぎんこう│りれき │   ※保護者ページはホームの
└─────┴─────┴─────┴─────┘      すみの小さなボタンから
```

### 3.1 ホーム
- おさいふ残高・ぎんこう残高・合計を大きく表示
- アプリを開いたとき利息がついていたら「りそくが ○円 つきました!」のお知らせを表示
- **おこづかいリマインダー**(§9)
- 今月のもらった額/使った額のミニサマリー
- 右上に小さな「保護者」ボタン

### 3.2 きろく(収支入力)
- 「もらった」「つかった」の2択 → 金額(テンキー風の大きなボタン)→ カテゴリ → メモ(任意)
- カテゴリ
  - もらった: おこづかい / おてつだい / お年玉 / プレゼント / その他
  - つかった: おかし / おもちゃ / 文ぼう具 / 本 / その他

### 3.3 ぎんこう(疑似口座) ★最重要
- 口座残高と年利を表示
- 「あずける」: おさいふ → 口座(おさいふ残高が上限)
- 「ひきだす」: 口座 → おさいふ(自由に引き出し可、口座残高が上限)
- 「このままあずけると…」: 1年後・3年後の予想額を表示して複利を実感させる

### 3.4 りれき
- おさいふの収支と口座の入出金・利息を時系列で一覧表示(月ごとに区切り)

### 3.5 保護者ページ(閲覧用)
- 4けたの暗証番号でロック(初回アクセス時に設定。localStorage 保存の簡易的な抑止力)
- **施錠のタイミング**: 解除状態は保護者ページに滞在している間だけ保持し、
  以下のいずれかで即座に施錠する(再入場時は必ず暗証番号を要求)
  - 保護者ページから他のタブへ移動したとき
  - アプリをバックグラウンドにした/タブを離れたとき(`visibilitychange`)
  - データリセットを実行したとき
- 内容:
  - 残高サマリー・全履歴の閲覧
  - **年利の設定**(初期値 10%、0〜100% の数値入力)
  - バックアップ(JSONファイル保存 / CSV保存 / ファイルから復元。§7参照)
  - 全データリセット(2段階確認)
  - 暗証番号の変更

## 4. データ設計

`localStorage["okozukai-app-v1"]` に以下の JSON を保存する。

```json
{
  "version": 1,
  "wallet": {
    "transactions": [
      { "id": "…", "date": "2026-07-09", "type": "in", "amount": 500,
        "category": "おこづかい", "memo": "" }
    ]
  },
  "bank": {
    "balance": 10000,
    "annualRate": 10,
    "lastInterestYm": "2026-07",
    "history": [
      { "id": "…", "date": "2026-07-09", "type": "deposit",
        "amount": 10000, "balanceAfter": 10000 }
    ]
  },
  "settings": { "parentPin": "1234" },
  "sync": { "enabled": true, "endpoint": "...", "secret": "...",
            "revision": 42, "dirty": false, "lastSyncAt": "..." }
}
```

- おさいふ残高は `transactions` から毎回計算(二重管理しない)
- 口座は `balance` を正とし、`history` は記録用
- `bank.history.type`: `deposit`(あずけ入れ) / `withdraw`(ひき出し) / `interest`(りそく)
- 「あずける/ひきだす」はおさいふ側にも `type: "out"/"in"`・カテゴリ「ぎんこう」で記録し、両者の整合を保つ

## 5. 利息計算(複利)ロジック

**タイミング**: アプリ起動時(ページ読み込み時)に一括計算。

1. 現在の年月 `nowYm` と `lastInterestYm` の差を **カレンダー月数** で求める
   (例: `2026-05` → `2026-07` なら 2 か月)
2. 経過月数ぶんループし、毎月:
   `利息 = floor(残高 × 年利% ÷ 100 ÷ 12)` を残高に加算(**月複利**)
   - 1円未満は切り捨て。利息が 0 円の月は履歴に記録しない
3. 各月の利息を `history` に `interest` として記録(日付はその月の1日)
4. `lastInterestYm = nowYm` に更新して保存
5. 合計利息 > 0 ならホームでお知らせ表示

補足:
- `lastInterestYm` は初期化時に現在の年月をセット(過去にさかのぼって付かない)
- 残高 0 円の月は利息なし
- 年利を変更した場合、**次の計算から**新しい年利を使う(過去分の再計算はしない)
- 端末の時計が過去に戻っていた場合(経過月数が負)は何もしない

## 6. UI 方針

- ビューポート幅 375〜768px を想定したモバイルレイアウト
- ボタン・タップ領域は 48px 以上、金額入力は大きなテンキー
- 丸み・パステル調のやさしい配色、金額は 3桁区切り+「円」
- 効果的な箇所に絵文字を使用(🐷 💰 🏦 など)
- `user-scalable=no` は使わず、入力フォントは 16px 以上(iOS の自動ズーム防止)

## 7. バックアップ(データ消失対策)

`localStorage` はブラウザの履歴削除や iOS の自動クリーンアップ(ITP)で消える可能性があるため、
以下の対策を実装する。

### 7.1 ファイルへのバックアップ / 復元(保護者ページ)
- **JSONバックアップ**: 全データを `okozukai-backup-YYYY-MM-DD.json` としてダウンロード。
  iPad では「ファイル」アプリ(iCloud Drive)に保存できる。保存時に `settings.lastBackupAt` を更新
- **CSV保存**: 全履歴(おさいふ+銀行)を日付順の CSV でダウンロード(UTF-8 BOM 付き、Excel/Numbers 閲覧用。復元不可)
- **復元**: ファイル選択で JSON を読み込み、確認ダイアログの上で全データを上書き

### 7.2 バックアップリマインダー
- データが 1 件以上あり、最終バックアップが **未実施 または 30日以上前** の場合、
  ホーム画面に保護者向けバナーを表示(タップで保護者ページへ)

### 7.3 ストレージの自動削除対策
- 起動時に `navigator.storage.persist()` を要求(対応ブラウザのみ)
- 運用上の推奨: Safari の「ホーム画面に追加」から利用する
  (ホーム画面 Web アプリは iOS の 7 日間未使用時のストレージ削除の対象外)

## 8. ホーム画面アイコン / インストール

iOS の「ホーム画面に追加」で使われるのは **favicon ではなく `apple-touch-icon`** のため、
マスコットを 180×180 の PNG(不透明・角丸なし。角丸は iOS 側で自動適用)として書き出し、
以下を `<head>` で宣言する。

```html
<link rel="apple-touch-icon" href="apple-touch-icon.png">
<link rel="icon" type="image/png" sizes="32x32" href="favicon-32.png">
<link rel="icon" type="image/png" sizes="512x512" href="icon-512.png">
<link rel="manifest" href="manifest.webmanifest">
<meta name="apple-mobile-web-app-title" content="おこづかい">
```

- iOS は SVG の apple-touch-icon を扱えないため **PNG 必須**。透過部分は黒く塗られるので背景は不透明にする
- ホーム画面での表示名は `apple-mobile-web-app-title`(長いと省略されるため「おこづかい」)
- `manifest.webmanifest` は Android/デスクトップ Chrome 用(iOS では上記 meta/link が優先される)
- **配信は GitHub Pages で問題ない**(静的ファイルをそのまま配信でき、HTTPS も自動)。
  ただしアイコンは `file://` で開いた場合には効かないため、必ず URL 経由で開いてホーム画面に追加する

## 9. おこづかいリマインダー

**背景**: ブラウザには「未来の時刻に自分で通知を鳴らす」仕組みがなく、
毎月1日の端末通知を出すには Web Push = サーバーが必須になる(端末内完結の方針と相反する)。
そのため**アプリ内での声かけ**で代替する。

- 判定: 当月に `type: "in"` かつ `category: "おこづかい"` の記録が **1件もなければ** リマインド対象
  (お年玉など他カテゴリはカウントしない/前月の記録もカウントしない)
- 表示: ホームにピンクのバナー「○月の おこづかい は もらったかな?」+ マスコットのセリフ
- バナーをタップすると「きろく」タブへ移動し、**「もらった」「おこづかい」を選択済み**の状態にする
- 当月ぶんを記録した時点で自動的に消える
- マスコットのセリフ優先度: りそく > おこづかいの声かけ > ふつうのひとこと
- 補助(アプリ外): iOS ショートカットの「毎月1日」オートメーションで通知を出す運用を推奨

## 11. データ同期(Google スプレッドシート)

任意機能。詳細は `設計_データ同期.md`、保護者向け手順は `同期セットアップ手順.md` を参照。

- `localStorage` を正とし、スプレッドシートは全件スナップショットの「鏡」
- 保護者ページで接続URLと合言葉を設定したときのみ有効(未設定なら完全ローカル動作)
- 変更のたびに5秒デバウンスで送信。失敗してもアプリは止めず、あとで自動再送
- ローカルが空のときだけ自動復元する(未送信の記録を失わないため)
- 同期が正常な間はバックアップ催促を表示しない。7日以上同期できない場合は警告
